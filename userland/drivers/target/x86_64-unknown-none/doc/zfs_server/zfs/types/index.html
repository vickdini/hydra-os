§Hydra ZFS On-Disk Format (version 2)

§Subsystem Role & Architecture

This module defines the core on-disk structures, magic numbers, constants, and serialization helpers for Hydra’s OpenZFS filesystem implementation. All on-disk structures are little-endian and operate within uniform 4 KiB physical and logical block frames.

§Architectural Rationale & Layout

The layout follows a copy-on-write Merkle tree design rooted in the active uberblock:

block 0                     VdevLabel (pool geometry, never rewritten after creation)
blocks 1 ..= 32             Uberblock ring (txg N lives in slot N % 32)
blocks 33 .. 33+B           Space bitmap (1 bit per block, B = total_blocks / 32768)
blocks data_start ..        Copy-on-write data: file data, indirect blocks, dnode array

Every object (file, directory, symlink, the dnode array itself) is described by a 512-byte DnodePhys whose three top-level BlockPointers root a tree of 64-way indirect blocks. The dnode for object N lives at byte N * 512 of the meta object, whose own dnode is embedded in the active Uberblock. A commit (transaction group) writes changed blocks to fresh locations bottom-up and finishes by writing a new uberblock, so the on-disk state is always a consistent tree.

§Key Types & Interfaces

  • Fletcher4: 256-bit checksum accumulator protecting labels, block pointers, and uberblocks.
  • BlockPointer: 64-byte block descriptor storing LBA, birth TXG, compression, and checksum.
  • DnodePhys: 512-byte inode equivalent holding POSIX attributes, bonus buffer, and block pointers.
  • VdevLabel: Persistent geometry descriptor on block 0 storing partition metrics and pool GUID.
  • Uberblock: Transactional root tracking active meta-dnode and transaction state.

§Hardware & Privilege Semantics

These structures directly represent on-disk byte arrays read from or written to non-volatile storage (ATA drives or RAM backing). Integrity is validated via hardware/software Fletcher-4 checksum verification before any block is accepted by higher layers.

ZFS Block Pointer (blkptr_t, 64 bytes): where a block lives, when it was written, and the checksum its contents must match. block == 0 is a hole (reads as zeroes).

Uberblock
ZFS Uberblock: root of the pool’s Merkle tree for one transaction group.
VdevLabel
On-disk vdev label (block 0): fixed pool geometry.
