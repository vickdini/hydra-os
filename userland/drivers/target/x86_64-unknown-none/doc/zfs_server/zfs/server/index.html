§Hydra ZFS File Server

§Subsystem Role & Architecture

This module provides the user-facing microkernel file server coordinating Hydra’s OpenZFS storage stack. It integrates the storage pool allocator (SPA), data management unit (DMU), ZFS attribute processor (ZAP), and POSIX layer (ZPL).

§Key Types & Interfaces

  • DatasetRecord: In-memory and on-disk representation of a ZFS dataset or snapshot.
  • ZfsServer: Main server state managing pool mounts, transaction groups, and caches.
  • ZFS_SERVER: Global mutex protecting the active file server instance.
  • init_server, with_server: Entry points to initialize and access the server safely.

§Concurrency & Hardware Semantics

Kernel and user-space threads access the server through the ZFS_SERVER spinlock. Dirty block counts are tracked to trigger automatic syncs when threshold capacity is reached. Unlinked inodes with open references are retained until the final handle closes.
