The kernel’s requests and their encoding, shared with the kernel.

§File System Protocol: the kernel’s requests to the ZFS file server

The OpenZFS implementation runs as a Ring 3 program (userland/drivers/zfs-server); the kernel’s file layer asks it for ZPL operations (POSIX-style, by inode) over ENDPOINT_ZFS_SERVER. This module is shared by both sides (the server includes it with #[path]): the operation codes, the types they carry, and their encoding in the service window.

§Wire format

A request is a message whose label is the operation; its parameters are encoded in the window from offset 0 (Writer: little-endian u64s and length-prefixed byte strings). The reply carries args = [status (value or -errno), value, reply bytes, events]: reply data is in the window from offset 0, and the inotify events the operation caused are at EVENT_OFFSET (the kernel delivers them to its watchers).
