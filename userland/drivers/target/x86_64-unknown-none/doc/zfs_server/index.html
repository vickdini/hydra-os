§Hydra ZFS file server

Hydra’s OpenZFS implementation (pool, DMU, ZAP directories, POSIX layer), in Ring 3 in an address space of its own. It owns the pool: it imports it at startup through the disk driver (ata-driver, whose service window it attaches) and answers the kernel’s file system requests on ENDPOINT_ZFS_SERVER (see zfs/fsproto.rs for the protocol).

The ZFS sources were the kernel’s; the modules below this comment give them what the kernel gave them: 4 KiB buffers for the block cache (heap pages instead of physical frames), the clock, the disk driver, and inotify (events are collected per request and handed back to the kernel, which delivers them to its watchers).

Calls to the disk driver, as the kernel’s ipc module made them.

4 KiB buffers for the block cache and dirty data. In the kernel these were physical frames reached through its identity mapping; here they are page-aligned heap blocks, named by their address, with the same reference counting.
task
Restarting the disk driver is the kernel’s business: a call to a dead driver restarts it.

The OpenZFS implementation.
