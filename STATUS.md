# Group G - Installer app & first boot (branch i-setup)
Current step: first-start test in a VM, now also logging in as the new user (running)
Works so far:
- Decision: our own installer window in Python + PyQt6 (like Hydra Apps), NOT Calamares. Why: Calamares is in Ubuntu 26.04 (3.3.14) but its disk page needs KPMcore + libparted + udev, which see only "known" Linux filesystems and real block devices; Hydra's pool partition is neither, and the installer must never mount the target. Its install modules (unpackfs, bootloader, users) all work by mounting the new system and changing files inside it, which our design forbids (settings are applied at first boot instead). It would also pull in about 30 extra libraries (Qt Quick/QML, KF6 parts, yaml-cpp, os-prober).
- The installer window inside Hydra's KDE desktop (VM): all pages shown and filled in, then a REAL installation through the window onto a 1 GB test disk image file finished with "Hydra is installed" (pictures: scratch/g-vm-shots). The disk then had the GPT, the start-up partition with the kernel in both places and the settings file.
- Disk-writing helper on a 2 GB disk image file (WSL): stand-in pool image written skipping empty blocks, read back and compared: identical.
- First start (VM, settings file put on the boot medium as the installer would): the kernel picks the file up and hands it to the system; before the login screen the account "Anna Schmidt" (anna, administrator: groups sudo, adm, audio, video...) is created, computer name anna-pc, time zone Europe/Berlin, German keyboard, German language (login screen showed "Montag, 16. November"), a new machine id; the settings file is deleted afterwards.
- Not possible yet: installing onto a real second disk and starting from it (needs Group E's disk devices and boot-from-partition; Group F's clean image).
